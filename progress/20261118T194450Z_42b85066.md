# 2026-11-18, feature session (#38: unit propagation in `search`)

- `core/src/lib.rs`: `search(p, t, f)` works on a partial assignment: atom `x` is true if `t[x]`,
  false if `f[x]`, unset otherwise. Each call first runs `find_unit`, which returns the result of
  `clause_unit` for the first clause that is falsified (the branch is cut) or unit (its unset
  literal is set, and `search` recurses with one atom more set). Without such a clause,
  `cc_conflict` (closure of the true atoms, then `false_joined` on the false atoms) cuts the branch.
  Otherwise `search` branches on `first_unset`, or at the leaf calls `prop_holds`/`theory_check` as
  before. Each call sets one atom, so the fuel bound (`length atoms + 1`) is unchanged.
  `some_clause_falsified`/`clause_falsified` (#34) and `prefix_conflict`/`diseqs_broken` (#37) are
  gone: `find_unit` and `cc_conflict` cut the same branches and more. `cc_conflict` runs at every
  decision node, which is cheap now that propagation removes most nodes.
- `clause_unit` has no mutable local. A first version with a mutable `usize` counter reordered the
  locale's prisms (the new mutable type came first in the file); a `bool` version kept the locale
  but its loop contract (mutable local plus early `return`) made the Pool Server time out. It now
  combines `some_lit_true` and `unset_lit(t, f, c, skip)`: two passes, each a plain loop. `urust/`:
  0 placeholders, no new stubs, the locale is unchanged.
- Proofs: `QFUF_Pure` replaces `ext_ok p a k` with `pext p t f` (some model extends the partial
  assignment), with `pext_conflict`, `pext_unit` (the key fact: a unit literal is forced),
  `pext_branch`, `pext_leaf`, `pext_cc_conflict`, `unset_count` (the fuel measure). The old
  `ext_ok` lemmas were removed. `QFUF_Proof` was split: `QFUF_Contracts` holds the contracts of the
  helper functions (new: `some_lit_true`, `unset_lit`, `clause_unit` with `unit_result`,
  `find_unit` with `find_result`, `first_unset`, `false_apart`, `false_joined`, `cc_conflict`), and
  `QFUF_Proof` holds the search, `solve_spec` and the theorems. The split was needed because the
  Pool Server's Java backend ran out of heap (OOM in `sync_document`) on the single file.
  `search_contract k p t f` has the same shape (precondition `unset_count t f < k`, postcondition
  `None ⟶ ¬ pext p t f`). `solve_spec`, `solve_correct` and `check_sat_correct` are unchanged.
