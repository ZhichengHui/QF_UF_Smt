# 2026-11-18, feature session (#51: why NEQ, PEQ, SEQ, QG and large eq_diamond stay unsolved)

Analysis only. No change to `core/`, `urust/`, `proof/`, `spec/` or `bench/`.

- **Measured:** PR #42's branch (`origin/agent/42b85066`, 240d487), with temporary counters in
  `search` (not committed). Re-measured result: **79/101**. Unsolved: eq_diamond13..20, NEQ 4/4,
  PEQ018_size4/5, QG iso_brn002/010/054 and dead_dnd001, SEQ 4/6. #51's "QG 4/10, SEQ 4/6" was
  swapped: it is QG 6/10 solved, SEQ 2/6.
- **Comments:**
  - On #28: the per-instance table, the diagnosis and the ranked steps
    (https://github.com/ZhichengHui/QF_UF_Smt/issues/28#issuecomment-6991599810).
  - On #45 and #50: the parts that bear on them.
- **Findings:**
  - `cc_conflict` takes 85–99.7 % of the run time on every unsolved instance, `find_unit` 1–8 %.
  - 30–50 % of the terms are duplicates.
  - QG needs theory propagation: at each conflict-free node the closure already implies 27–77
    atoms, and z3 needs at most 7 conflicts on the iso instances.
  - SEQ needs learning: the conflicts repeat.
  - eq_diamond needs equality elimination as preprocessing (z3's `solve-eqs`). z3's search alone
    needs 528,600 conflicts on eq_diamond20.
  - NEQ and PEQ018 need full CDCL (1UIP analysis, backjumping of 15–71 levels).
- **Prototypes** (unverified, scratch only): fast closure F, hash-consing H, learning L, theory
  propagation P. With `bench/run.sh` and models checked: F+H+P solves 83/101 and F+H+L+P solves
  85/101, both with 0 WRONG. Learning with deletion-minimised explanations is too slow (it loses
  PEQ012 and dead_dnd001): explanations must come from the closure.
- **Ranking** (beyond #50 and #45):
  1. theory propagation (+4 QG);
  2. equality-elimination preprocessing (+8 eq_diamond);
  3. 1UIP and backjumping, then a dynamic decision order (NEQ, PEQ018);
  4. hash-consing (supporting).
- **Lessons:**
  - `pgrep -f NAME` inside an `until` loop matches the loop's own command line, so the loop never
    ends. Wait for a file or an output marker instead.
  - Functions run through `xargs bash -c` see only exported variables.
  - Two constants of the same symbol are congruent: a closure that skips terms without arguments
    misses conflicts. This is the same trap as in #35.
- **Checks:** `git diff --stat main` shows only this file. The release binary was rebuilt from
  main's source.
