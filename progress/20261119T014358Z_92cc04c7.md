# 2026-11-19, feature session (#45: learn clauses from congruence-closure conflicts)

- `search` now carries a vector of learned clauses `l` and returns it with the result.
  `next_unit` propagates over the problem's clauses, then over `l`. When `cc_conflict` (which now
  returns the conflicting false atom `c`) cuts a branch, `search` learns
  `conflict_clause(explain(p, t, c), c)`: "some atom of the explanation is false, or `c` is true".
- Explanation (`explain`): a merge log, i.e. the closure of the true atoms rerun while logging
  every merge as an edge (atom, or congruent pair); this costs one extra closure per conflict.
  - The log's edges form a forest, and the arguments of a congruence edge are joined by earlier
    edges. So the path between the two sides (BFS), with the argument pairs of its congruence
    edges explained recursively, is a well-founded explanation.
  - It is confirmed by `rows_join`, a closure restricted to the terms of the congruence edges
    used, and falls back to all true atoms otherwise. Only `rows_join` matters for soundness: a
    restricted closure is sound, though not closed.
- Approaches tried and dropped (all measured on the suite):
  1. Deletion-based minimization: one closure per candidate atom. 73/101, losing QG.
  2. A relevant-class filter plus halving chunks: still slower than main on PEQ/QG.
  3. Shortest paths over the final closure: 99% of explanations circular on SEQ.
  The merge log fixed both problems.
- Proofs:
  - `QFUF_Pure`: `clause_ok`, a clause that every model of the problem satisfies.
    `pext_unit`/`pext_conflict` now take `clause_ok`, and `conflict_clause_ok` proves the learned
    clause valid.
  - `QFUF_Contracts`: `find_unit` over any `clauses_ok` list; new `next_unit`, `first_joined`;
    `cc_conflict` returns `conflict_result`.
  - New theory `QFUF_Explain`: contracts of the restricted closure, the merge log, BFS, `walk`,
    `path_explain`, `explain`, `conflict_clause`, `learn`. The heuristic parts use bounds-checked
    helpers (`get_or`, `set_at`, `set_true`), so their contracts only state lengths.
  - `QFUF_Proof`: `search_contract` with `clauses_ok p l` before and after. `solve_spec`,
    `solve_correct` and `check_sat_correct` keep their statements, and `spec/` is unchanged.
  - The `solve` prism list in `proof/core_spec` gains `prism_7 prism_9 prism_10`.
- Bounds: `clauses_ok` puts no bound on the number of learned clauses, which the search tree does
  not bound. `clause_unit` now accepts clauses with fewer than `2^64` literals, because a learned
  clause can have `m + 1 = 2^63` literals.
- Code placement: the new functions with mutable `usize`, `Vec<Lit>` and `Vec<Clause>` locals sit
  at the end of `lib.rs`, so that the generated locale (and `spec/`) is unchanged. Reported as
  ZhichengHui/AutoCorrodeRustFrontEnd#20.
- Benchmark `QF_UF_Smt-2026-11-18`, main and branch side by side: 79 → 84/101, 0 WRONG, none lost.
  - Time on the 79 instances both solve: 95.1 s → 53.1 s.
  - New: SEQ015_3, SEQ032_3, SEQ042_2, SEQ050_2, QG iso_brn002.
- The aim of 82 is met, but not on eq_diamond. eq_diamond13+ stay out of reach of any learning
  over the input atoms: with the input atoms alone these diamonds take exponentially many
  conflicts (Strichman/Rozanov). They need new equality atoms (e.g. `x0 = x_i`, dynamic
  Ackermannization / splitting on demand). Learning still speeds up eq_diamond10–12 2.8×.
- Remaining costs: PEQ019 and two QG instances are 15–25% slower (one extra closure per conflict).
  Cheaper closures (#50) shrink both the cut and the explanation.
- Tests: `core/tests/learn.rs`.
  - A closure conflict repeated under 2^40 branches: main times out; the branch takes 0.2 s.
  - Path explanations on diamond chains, sat and unsat, checked against z3.

- Lessons for later sessions:
  - For an explanation, rerun the closure with a merge log. Shortest paths over the final
    partition are circular, and deletion costs one closure per atom.
  - Contracts whose precondition has an existential reference state (as for `finish`) avoid
    crush's early instantiation of ghost parameters in loops. Subgoals then gain parameters for
    the opened existentials (`subgoal for g1 v1 ... ref`).
  - A theory in the task heap cannot be checked from a working copy of the same name
    (duplicate facts); keep only finished theories in the heap.
