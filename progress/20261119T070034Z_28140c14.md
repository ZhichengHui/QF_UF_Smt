# 2026-11-19, feature session (#56: theory propagation in the search)

- `search` now propagates through the closure. When there is no unit and no closure conflict, it
  sets every unset atom the closure decides, then recurses (`cc_propagate`, which replaces
  `cc_conflict` and reuses its closure).
  - True: an atom whose two sides the closure joins (`joined_unset`).
  - False: an atom whose two sides lie in the classes of the two sides of an atom already set
    false (`separated_unset`). The classes of the false atoms are collected once per node
    (`false_pairs`, `has_pair`).
  - The recursion (`differs`) happens only if something changed. Every such call sets at least one
    atom, so the fuel argument is unchanged.
  - No clause is learned for a propagated literal; the proof justifies it directly
    (`pext_implied`).
- Measurements behind the design:
  - True propagation alone gained nothing on the suite (84/101); the false half solves the four
    QG instances.
  - A flag that skipped the closure after a propagation step was slower. A second round finds
    more: newly false atoms separate new pairs of classes. It was dropped.
  - eq_diamond10–12 are 1.3–1.5× slower. The search tree keeps its size, but the closure runs at
    about twice as many nodes (units and propagation interleave). An incremental closure would
    remove that cost.
- Proofs: new theory `proof/QFUF_Propagate.thy`, between `QFUF_Explain` and `QFUF_Proof`.
  - Pure facts: `sep_by`, `implied_ok`, `pext_implied`, `implied_fuel`.
  - Contracts of the new functions. `false_joined_keep_contract` is `false_joined` with the
    closure invariant kept, so that `implied` can use the same closure.
  - `QFUF_Contracts`: the contract of `cc_conflict` is removed (the function is gone).
  - `QFUF_Proof`: `search_rec_step_spec` (review #39 item 5 / #49) no longer depends on the order
    of the goals `auto` leaves. One repeated `rule …; assumption` closes them all, using step
    lemmas stated in the exact form of the goals: `step_implied`, `step_implied_fuel`,
    `step_learn`, `step_conflict`, `step_falsified`, `step_branch_none`, `step_leaf_some`.
  - `solve_spec`, `solve_correct`, `check_sat_correct` keep their statements, and `spec/` is
    unchanged.
- Generated code: `urust/` regenerated, `PLACEHOLDERS.txt` 0, templates unchanged, locale
  unchanged (the new functions with mutable locals sit at the end of `lib.rs`). No framework gap.
- Benchmark `QF_UF_Smt-2026-11-18`, main (with #55) and branch built side by side, run one after
  the other with JOBS=6: 84 → 87/101, 0 WRONG, none lost.
  - Time on the 84 both solve: 63.5 s → 26.4 s.
  - New: QG iso_brn010, iso_brn054 (0.1 s each) and dead_dnd001 (17.4 s). iso_brn001–008 and
    068 go from 2–16 s to under 0.1 s, PEQ019 from 4.4 s to 1.3 s.
  - Slower: eq_diamond12 8.1 → 10.9 s, eq_diamond11 2.1 → 3.4 s.

- Tests: `core/tests/propagate.rs` builds quasigroups (latin squares over distinct constants),
  some with idempotence, commutativity and the QG5 identity `((y*x)*y)*y = x`. Answers are
  checked against z3, and models by an evaluator. The idempotent QG5 of order 8 takes 5 s with
  propagation; main does not answer within the 20 s limit (32 s measured).
- Verification:
  - `cargo test --release` green; `tools/fuzz.py` seeds 5601 and 5602, 200 problems each, no
    mismatch.
  - `tools/check-spec.sh` ok; no `sorry`/`oops`/`quick_and_dirty`.
  - Pool Server: `QFUF_Propagate` and `QFUF_Proof` without errors, on a task heap holding the
    theories up to `QFUF_Explain`. The heap build itself checks `QFUF_Contracts`.
  - `isabelle-check` EXIT 0.
- Lessons:
  - A theory that is in the task heap cannot be checked from a working copy, even renamed: the
    locale `QFUF_ctx` already carries its declarations (duplicate constants). Put in the heap only
    theories that will not change again.
  - Contracts whose post-condition states list equality (`r = (t1 ≠ t)`) instead of a pointwise
    `∀i` let `auto` substitute, and leave far fewer goals.
  - Goals of `crush_base` + `auto` can be closed in any order by
    `apply ((rule l1 l2 …; assumption)+)` with step lemmas in the exact form of the goals.
- Remaining: eq_diamond13+ (needs new atoms, see #45) and NEQ/SEQ timeouts. The closure is still
  recomputed from scratch at every node; an incremental closure would make propagation cheaper.
