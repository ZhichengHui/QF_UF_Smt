# 2026-11-19, feature session (#65: incremental closure and cheaper closure reasons)

Partial: deliverables 1, 2, 3 and 4 are done, but the aim (+2 among NEQ/PEQ) is not met.

- Incremental closure (`cc_step`, `core/src/lib.rs`).
  - `cdcl` now carries a partition `rep` and its merge log `xs`, `ys`, `ls` down its recursion.
    `solve` starts it with `root_log`: the closure of no equalities, plus `merge_log` of no atoms,
    which is the same partition.
  - `cc_step` replaces `cc_propagate` in `cdcl`. It copies the carried partition and log, merges
    the atoms set true since (`log_atoms`, which merges only atoms whose sides are in different
    classes), then runs rounds of `round_moved`. A round rescans, against every term
    (`log_col`), only the terms an argument of which changed its representative since the round
    before (`moved_rows`, `copy_into`).
  - Completeness: two terms that become congruent have an argument pair whose classes were
    merged, and a merge changes the representative of one of the two classes. So a closed
    partition stays closed. When only `f` changes, nothing is merged and nothing is rescanned.
  - `search` (the fallback) keeps `cc_propagate`.
- Cheaper closure reasons.
  - `path_explain_log` reads an explanation off a given log; `path_explain` is now `merge_log` +
    `path_explain_log`.
  - `theory_reason` (and through it `reason`, `resolve_step`, `analyze`, `on_conflict`) takes
    the carried log instead of rebuilding a log per resolved atom. Closure conflicts in `cdcl` use
    `explain_log` on the log of `cc_step`.
  - Every merge joins two classes, so the log is a forest, and the path between two terms does
    not change once they are joined. The explanation from the later log is therefore the one of
    the node that propagated the atom. Its atoms were set before it, so `true_before` is gone.
  - Soundness still rests only on `rows_join`; the log has no invariant.
- `separated_unset`: `false_sides` flags the classes of the sides of the false atoms, and
  `has_pair` runs only for atoms whose two sides are flagged. This took `implied` from 32 % to
  2 % of the time on NEQ032.
- Tried and dropped: union by size (merge the smaller class into the larger, `class_size`).
  PEQ019 went 0.28 → 0.22 s, nothing else changed. Its contract needed the existential
  post-state handling of `assert_eqs_spec`.
- Proofs:
  - `proof/QFUF_Incremental.thy` (new, between `QFUF_Analyze` and `QFUF_Proof`). Invariant
    `rep_for p t rs`: each class lies in the congruence closure of the atoms set true in `t`
    (`rep_sound`), plus lengths and representative bounds. It is monotone in `t`
    (`rep_for_mono`, `rep_for_update`, `rep_for_implied`) and follows from `cc_inv p {}`
    (`rep_for_empty`). Contracts for `log_atoms` (`cc_inv` of all atoms set true, through
    `atoms_inv`), `arg_moved`, `moved_rows`, `log_col`, `log_moved`, `copy_into`,
    `round_moved`, `close_moved`, `cc_step`, `root_log`. Closedness is not proved: it only
    matters for speed.
  - `QFUF_Explain`: `path_explain_log_spec`, `explain_log_spec`.
  - `QFUF_Propagate`: `false_sides_spec`, `flag_at_spec`. `implied_contract` now returns the
    partition with `cc_inv` and `implied_ok` on the same list, which `cc_step` needs.
  - `QFUF_Analyze`: new signatures; `true_before_spec` removed.
  - `QFUF_Proof`: `cdcl_contract` takes `rep` and requires `rep_for p t rep`. Two step lemmas
    were added to the rule list (`rep_for_update`, `rep_for_implied`). `solve_spec` and
    `solve_vals_spec` use `root_log_spec` and `rep_for_empty`. `solve_correct` and
    `check_sat_correct` are unchanged, and so is `spec/`.
